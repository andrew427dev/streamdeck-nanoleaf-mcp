# 미러링 안정성 보완 계획

상태: **계획만 작성 — 미구현·미설치·미배포**

기준일: 2026-10-18

대상: v0.5.0-beta.2 이후의 macOS / USB PC Screen Mirror Lightstrip(NL82K2)

이 계획은 [beta.2 설치 검증과 오류·복구 기록](VALIDATION.md)에 근거합니다. 문서 반영은 기존 설치본·프로필·버튼·다이얼·Nanoleaf Desktop 설정과 저장된 씬을 변경하지 않습니다. Marketplace 제출은 범위에서 제외합니다.

## 1. 현재 결론과 해결 목표

- 정확한 beta.2 공개 패키지의 설치·기존 설정 유지와 실제 전원 제어는 확인했습니다.
- 미러링은 엔진 상태가 실행 중이고 Desktop에 Streaming으로 표시돼도 실제 조명이 화면 색상을 따르지 않는 사례가 있었습니다.
- 사용자가 Desktop을 완전히 종료하고 다시 열어 복구됐다고 보고했습니다. 코드 수정으로 해결한 것이 아니며, 원인과 재발 조건은 확정되지 않았습니다.
- 목표는 **상태를 오해하지 않게 표시하고, 재발 시 원인을 구분할 최소한의 정보를 확보한 뒤, 증거가 있는 제어 오류만 수정하는 것**입니다. Desktop 내부 캡처·USB 출력 문제까지 플러그인으로 해결할 수 있다고 전제하지 않습니다.

현재 확인한 MCP 상태 응답은 실행 여부와 모드입니다. 실제 캡처 프레임의 최신성이나 USB 전달·조명 출력 성공은 이 응답만으로 판별할 수 없습니다. 정적인 화면에서 조명 색상이 유지되는 것도 정상일 수 있으므로, 색상이 변하지 않는다는 이유만으로 자동 오류 판정을 하지 않습니다.

## 2. 우선순위와 완료 조건

| 우선순위 | 계획 항목 | 완료 조건 |
| --- | --- | --- |
| P0 | 실행 상태와 실제 출력의 의미 구분 | 명령 수락·엔진 실행·상태 확인 불가를 구분하고, 센서 근거 없이 실제 출력 성공으로 표시하지 않음 |
| P0 | 개인정보를 제외한 읽기 전용 진단 | 사용자가 요청한 진단으로 연결·기능 지원·상태·응답 시점·안전한 오류 분류를 확인하며 앱 실행이나 조명 변경은 발생하지 않음 |
| P1 | 오류 재현과 제어 경로 비교 | 같은 조건에서 플러그인/앱 직접 조작 결과와 실제 조명 반응을 별도로 기록하고, 재현 불가 시 그대로 명시 |
| P1 | 원인이 확인된 부분만 보완 | 변경 전 실패하는 재현 시험과 변경 후 통과하는 회귀 시험을 확보하고 기존 제어 안전 규칙 유지 |
| P1 | 정확한 후보 패키지 실기기 검증 | 미러링 기본 4개 항목, 기존 제어 회귀, 승인된 복구 시험과 설정 유지 확인 |
| P2 | 별도 복구 버튼의 필요성 판단 | 수동 안내로 충분한지 먼저 확인; 필요할 때만 대상 전체 영향·명시적 실행 조건을 다시 설계하고 승인 |

P0의 표시·진단 개선은 관측 가능성을 높이는 작업이지, 이번 출력 오류의 원인을 해결했다는 뜻이 아닙니다.

## 3. 표시와 진단 개선안

### 표시의 의미

- 기존 키의 켜짐/꺼짐 표시는 Desktop이 보고한 엔진 상태로 설명합니다. 제목·아이콘 크기 규칙과 사용자 지정 제목은 유지합니다.
- 설정 화면의 마지막 명령 결과에는 “엔진 실행 확인 / 실제 조명 출력은 직접 확인”처럼 검증 수준을 드러내는 문구를 검토합니다.
- 조회가 실패하거나 상태가 오래된 경우 이전 성공을 현재 정상 상태처럼 유지하지 않고 “상태 확인 불가”로 안내합니다.
- 실제 출력 미확인은 고장 확정이 아닙니다. 모든 정상 실행에 오류 삼각형을 표시하거나 초록색 성공 체크를 다시 도입하지 않습니다.

### 사용자가 요청하는 진단

1. 설정 화면에 읽기 전용 “연결·미러링 상태 확인” 기능을 우선 검토합니다. 새 물리 버튼을 필수로 추가하지 않습니다.
2. 플러그인 버전, 서버가 제공하는 경우의 Desktop 버전, 미러링 기능 지원, 조회 당시 실행 상태·모드, 응답 지연과 오류 분류를 확인합니다. 제공되지 않는 버전·상태는 추측하지 않습니다.
3. 상태 조회가 실패해도 Desktop을 실행하거나 미러링 시작·정지·전원·씬 명령을 보내지 않습니다.
4. 기존 공유 상태 조회에 불필요한 병렬 감시를 추가하지 않습니다. 읽기 요청의 시간·횟수에 한도를 두고, 프로필 이탈이나 설정 변경 후 오래된 결과가 새 화면을 덮지 않게 검증합니다.
5. 실제 출력의 정상 여부를 제공하는 공식 읽기 전용 인터페이스가 있는지 확인합니다. 없다면 “실제 출력 자동 감지 불가”를 유지하고, 디버깅 포트·앱 내부 코드 삽입·화면 캡처로 우회하지 않습니다.

### 개인정보 경계

진단은 기본적으로 메모리에서만 처리하며 자동 업로드·상시 로그 파일을 추가하지 않습니다. 향후 보고서 복사가 필요하면 사용자가 미리 확인한 허용 항목만 포함합니다.

제외 항목: 화면 이미지·색상 프레임·창 제목·장치 식별자·시리얼·계정·토큰·개인 경로·씬 이름·프로필 원본·Desktop 원본 로그. 오류 문구도 원문 그대로 복사하지 않고 안전한 분류로 변환합니다.

## 4. 재현·복구 검증 순서

1. 먼저 모의 응답 시험으로 상태 표현, 세션 만료, 시간 초과, 늦은 응답, 명령 중복 방지와 기존 제어 회귀를 확인합니다.
2. 실기기 시험은 별도 승인된 시간에 진행합니다. 시작 전 정확한 버전, 현재 엔진 상태, 대상 화면과 조명 상태를 확인합니다.
3. 증상이 재발하면 앱을 즉시 재시작하기 전에 한 번의 버튼 입력 전후 상태와 사용자가 관찰한 실제 출력을 기록합니다. 반복 전환으로 원래 상태를 잃지 않습니다.
4. 사용자가 승인한 경우 같은 화면·대상·모드에서 Desktop 자체 스위치로 OFF/ON을 한 차례 비교합니다. 이는 다른 대상의 스트리밍에도 영향을 줄 수 있습니다. 이번 사고에서는 이 비교가 완료되지 않았으므로 결과를 추정하지 않습니다.
5. 복구가 필요하면 사용자가 앱 완전 종료·재실행을 선택할 수 있도록 영향과 절차를 안내합니다. 전후 결과와 누가 어떤 조작을 했는지 기록합니다.
6. 플러그인 경로만 실패하는지, Desktop 직접 조작도 실패하는지, 재시작 없이 회복하는지 구분한 뒤 수정 대상을 결정합니다. 재현되지 않으면 “재현 불가 / 원인 미확정”으로 남깁니다.

자동 앱 종료·재시작, 실패 시 변경 명령 재전송, 임의의 정지 후 시작, 모드·화면·장치·배치·권한 변경은 기본 복구 동작으로 넣지 않습니다. 사용자 승인 없는 장시간 시험이나 모니터링도 시작하지 않습니다.

## 5. 시험 항목

다음은 **향후 합격 목표**이며, beta.2에서 이미 모두 통과했다는 뜻이 아닙니다.

| 범주 | 시험과 확인 기준 |
| --- | --- |
| 엔진과 출력 구분 | 모의 시험은 엔진 실행만 확인하고 실제 출력 성공을 주장하지 않음. 실기기에서는 선택된 화면 변화와 조명 반응을 사용자가 별도 확인 |
| 기본 미러링 | 시작, 정지와 이전 상태, 전환 2회, 앱 완전 종료 후 옵션 ON 시작의 4개 항목을 정확한 후보 패키지에서 재검증 |

| 기존 조명 제어 | 전원·씬·밝기 키, 밝기 다이얼·터치 표시·숫자 크기, Scene Browser 터치·누름 실행을 회귀 검증 |
| 제어 간 상호작용 | 미러링 실행 중 전원·씬·밝기 입력과 다른 스트리밍의 실제 결과를 기록. 자동 미러링 중지나 임의 씬 복원을 새 정책으로 넣지 않음 |
| 이전 상태 복원 | 저장 씬·단색·전원 OFF에서 시작한 경우와 중간 수동 조작을 각각 확인. 항상 원상 복원된다고 가정하지 않음 |
| 복구 조건 | 승인된 절전 복귀·USB 재연결·대상 화면 변경/재연결 후 엔진 상태와 실제 출력을 따로 확인 |
| 권한·배치·복수 대상 | 별도 승인된 시험 환경에서만 확인. 실제 시험하지 않은 구성·모드는 검증 완료로 표시하지 않음 |
| 설치·개인정보 | 정확한 패키지 파일 일치, 기존 동작·설정·제목 유지, 개인 정보 없는 진단 출력과 공개 패키지 확인 |

실기기 결과에는 버전, 사전 조건, 조작, API 상태, 사용자 관찰, 복구 조작, 결과를 분리해 기록합니다. 반복 횟수와 대기 시간도 실제 수행한 값만 적습니다. 한 번의 통과를 장시간 안정성 검증으로 확대하지 않습니다.

## 6. 실행 및 배포 기준

1. **이번 작업:** 검증·오류·복구 이력과 이 계획만 GitHub 문서에 반영합니다. 설치본과 배포 버전은 v0.5.0-beta.2로 유지합니다.
2. **다음 승인 후:** P0 표시·진단 구현과 모의 시험을 진행하고, 원인별 수정이 필요하면 실패 재현 시험부터 추가합니다.
3. **설치 승인 후:** 새 후보 패키지를 검증하고, 기존 설정의 의미상 비교를 전후로 수행합니다. 임시 프로필을 선택해도 플러그인 실행 파일은 다른 프로필과 공유되므로 격리 설치로 간주하지 않습니다.
4. **실기기 확인 후:** 통과 범위와 남은 한계를 문서화하고 별도 승인된 새 베타를 배포합니다. 이미 공개된 beta.2 태그·설치 파일·체크섬은 덮어쓰지 않습니다.
5. **Marketplace:** 이 작업과 분리해 보류합니다. 제출·업로드·심사 요청을 진행하지 않습니다.

완료 기준은 “이번 현상이 무조건 재발하지 않는다”가 아니라, 검증 수준을 정확히 표시하고, 재현된 제어 문제의 회귀 시험을 통과하며, 정확한 설치본에서 승인된 실기기 항목과 기존 설정 유지가 확인되는 것입니다.
