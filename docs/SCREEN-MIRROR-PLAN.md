# 화면 미러링 구현 기준과 실기기 검증 계획

2026-10-18 기준으로 Nanoleaf Desktop 3.0.1에는 로컬 MCP를 통한 화면 미러링 시작·정지·상태 조회 기능이 있습니다. 아래 기준으로 v0.5.0-beta.1 시험판에 미러링 키와 설명 문구를 구현해 테스트 프로필에 적용했습니다. 같은 날 사용자가 실제 시작 출력, 정지 후 이전 상태 복원, 전환 2회, 앱 완전 종료 후 시작 키의 자동 실행까지 4개 항목의 정상 작동을 확인했습니다. 정확한 결과는 [검증 기록](VALIDATION.md)에 보존합니다.

공개판 v0.5.0-beta.2는 이 구현과 검증 문서를 배포하며, 현재 설치본과 기존 설정은 교체하지 않습니다. 아래 표 전체가 실기기 통과했다는 의미는 아닙니다. 권한 오류, 복수 대상·다른 스트리밍과의 경합, 복원 조합별 결과와 미러링 중 절전·화면·USB 변경 등은 추가 검증 대상입니다.

## 확인된 동작과 제어 범위

Desktop의 Screen Mirror 화면에는 실행 스위치, 디스플레이 선택, 대상 장치, 배치, FPS와 4개 모드가 있습니다. NL82K2가 배치 가능한 대상에 표시되며 앱 내부에도 USB 스트리밍 활성화·프레임 전달 경로가 있습니다. 읽기 전용 상태 조회는 `isRunning: false`, `mode: "4D"`를 반환했습니다. 이는 명령 제공과 현재 엔진 상태를 확인한 것이며, 실제 미러링 출력 시험은 아닙니다.

| 로컬 MCP 명령 | 입력 | 응답 또는 역할 |
| --- | --- | --- |
| `get_screen_mirror_status` | `{}` | `isRunning`과 `mode` 조회 |
| `start_screen_mirror` | `{ "mode": "4D" }` 등 | Desktop에 설정된 대상 전체의 화면 미러링 시작 |
| `stop_screen_mirror` | `{}` | Desktop 화면 미러링 정지 |

모드는 `4D`, `Tranquility`, `Flow`, `Chameleon`입니다. 여기서 4D는 Desktop의 화면 가장자리 미러링 모드이며, NL69 카메라형 기기의 `set_4d_mode` 명령과 다릅니다.

이 명령에는 장치 ID가 없습니다. 현재 홈의 선택된 장치, 디스플레이, 배치와 FPS를 Desktop에서 가져오는 **앱 전체 제어**입니다. 다른 조명이 Desktop의 대상으로 선택되어 있으면 함께 영향을 받으므로 NL82K2 한 대에만 적용된다고 표시해서는 안 됩니다. 다른 모델까지 플러그인의 검증 범위가 확장되는 것도 아닙니다.

시작할 때 전달한 모드는 Desktop 설정에 저장됩니다. 1차 구현은 조회한 현재 모드를 그대로 사용하며, 모드·모니터·대상·배치를 변경하는 기능은 제외합니다. 시작은 다른 Desktop 스트리밍 기능을 중지할 수 있습니다.

중지는 조명 OFF 명령이 아닙니다. Desktop이 기억하는 이전 전원·색상·씬 상태로 복원을 시도하지만, 복원 정보가 없거나 중간에 다른 제어가 있었다면 결과가 달라질 수 있습니다. 플러그인은 임의로 전원을 끄거나 저장 씬을 다시 실행하지 않습니다.

## 버튼과 설정 설계

새 키 동작 `Screen Mirror`를 추가하고 동작을 **시작 / 정지 / 전환** 중에서 선택하도록 합니다. 식별자 후보는 `io.github.andrew427dev.nanoleaf-mcp.screen-mirror`이며 기존 동작 식별자는 유지합니다. 시작과 정지는 서로 다른 키에 배치할 수 있고, 전환은 하나의 키로 두 동작을 사용할 때 선택합니다.

설정 화면에는 다음을 표시합니다.

- 대상 설명: **Nanoleaf Desktop에서 선택한 미러링 장치 전체에 적용됩니다.** 기존 장치·씬 선택란은 표시하지 않습니다.
- 모드 설명: **Desktop에 설정된 현재 모드를 사용합니다.**
- 앱 실행 옵션: **앱이 꺼져 있으면 실행 후 제어**. 시작·전환에만 적용하며 기본값은 꺼짐입니다. 기존 버튼의 값은 변경하지 않습니다.
- 정지 동작은 앱을 새로 실행하지 않습니다. 연결 실패만으로 이미 정지했다고 단정하지 않고 상태 확인 불가로 안내합니다. Desktop의 별도 `Screen Mirror on App Launch` 설정도 변경하지 않습니다.
- 사전 준비: Desktop에서 화면 기록 권한, 화면 선택, 대상 조명과 배치를 먼저 설정합니다. 다른 스트리밍 기능이 중지될 수 있음을 함께 안내합니다.

키 표시 상태는 `화면 싱크 꺼짐`, `시작 중`, `화면 싱크 실행 중`, `정지 중`, `상태 확인 불가`로 구분합니다. 초록색 성공 체크는 다시 도입하지 않으며 사용자 제목·기존 크기 조정 규칙을 유지합니다. 실행 중 표시는 Desktop 캡처 엔진 상태이고, 모든 대상 조명의 실제 출력 성공을 뜻하지 않습니다.

## 명령 처리 규칙

1. 명시적인 키 입력에서만 필요에 따라 앱을 실행합니다. 키 표시 갱신, 설정 열기와 상태 새로고침은 앱을 실행하지 않습니다.
2. 현재 서버가 세 미러링 명령을 제공하는지 확인합니다. 미지원 버전에서는 설명을 표시하며 UI 클릭이나 디버깅 포트 방식으로 우회하지 않습니다.
3. 명령 직전에 상태를 다시 조회합니다. 시작 요청인데 이미 실행 중이거나 정지 요청인데 이미 정지되어 있으면 변경 명령 없이 완료합니다. 외부 앱에서 바꾼 상태도 반영합니다.
4. 앱이 이미 연결되어 있는 경우 전환은 성공적으로 읽은 상태를 반전합니다. 앱 실행이 필요했던 전환 요청은 **미러링 켜기**로 처리하고, 실행 후 상태를 읽어 이미 켜져 있으면 변경 없이 완료합니다. Desktop의 `Screen Mirror on App Launch`가 켜져 있어 자동으로 시작된 미러링을 첫 전환 요청이 다시 끄지 않도록 하기 위함입니다. 상태를 끝내 읽지 못하면 추측하여 명령을 보내지 않습니다.
5. 시작은 조회한 모드가 허용된 4개 값인지 검사한 뒤 한 번 전송합니다. 이미 실행 중인 미러링을 모드 변경 목적으로 자동 정지·재시작하지 않습니다.
6. 변경 명령에는 제한 시간을 두며 자동 재전송하지 않습니다. 시간 초과 시 읽기 전용 재조회로 결과를 확인합니다. 결과를 확인하지 못하면 성공·실패를 단정하지 않고 상태 확인 불가로 표시합니다.
7. 여러 키와 프로필이 공유하는 앱 전체 작업 잠금을 사용해 시작·정지 연타와 교차 요청을 차단합니다. 프로필 이탈·설정 변경·제거 후 아직 보내지 않은 요청은 취소하고, 이미 전송한 요청은 취소된 것으로 가장하지 않습니다.
8. 상태 조회는 화면에 보이는 미러링 키끼리 공유하고, 앱을 실행하지 않는 읽기 전용 방식으로 수행합니다. 늦게 도착한 응답이 새 상태를 덮어쓰지 않도록 합니다.

기존 장치별 전원·씬·밝기 잠금만으로는 앱 전체 미러링과의 경합을 막을 수 없습니다. 미러링 전환 처리 중에는 관련 변경 요청이 겹치지 않도록 제어 경로를 조정해야 합니다. 미러링 실행 중 기존 전원·씬·밝기 버튼을 눌렀을 때의 효과는 별도 실기기 시험으로 확인하고, 자동 정지 후 씬 실행 같은 새 정책은 이번 계획의 기본 동작에 넣지 않습니다.

## 코드 변경 범위

- `src/nanoleaf.mjs`: 미러링 전용 상태·시작·정지 메서드와 검증을 추가합니다. 기존 전원·씬 응답은 `results[]`이고 미러링 응답은 최상위 `{isRunning, mode}` 또는 `{ok:true}`이므로 같은 파서를 강제로 재사용하지 않습니다. 전송·세션·시간 제한 처리는 공유합니다.
- 새 `src/screen-mirror.mjs`: 상태 확인, 같은 상태 요청의 무변경 처리, 앱 전체 작업 잠금, 늦은 응답 무시와 결과 재확인을 담당하는 Module로 계획합니다. Interface에는 조회와 요청한 동작만 노출하고, 전송과 시간은 주입하여 실제 화면 캡처 없이 시험합니다.
- `src/controller.mjs`: 앱 실행·준비 확인에서 장치 ID 검증을 분리합니다. 미러링을 기존 단일 장치 제어인 것처럼 취급하지 않습니다.
- `src/plugin.mjs`, 키 표시, 설정 화면과 manifest: 새 동작만 추가하고 기존 식별자·설정값·조작 방식을 유지합니다.
- 개인정보 안내: 플러그인은 명령과 상태만 취급하며 화면 이미지·창 제목·미리보기는 수집하지 않는다고 설명합니다. 화면 캡처와 관련 권한은 Nanoleaf Desktop이 담당합니다.

## 권한과 오류 처리

Desktop UI에는 화면 기록 권한과 배치 확인 과정이 있지만, MCP 시작 경로는 같은 UI 사전 검사를 거치지 않습니다. 따라서 상태가 실행 중이라는 이유로 권한과 대상 장치가 정상이라고 추정하지 않습니다. 출력이 없거나 시작에 실패하면 Desktop에서 권한·모니터·장치 선택·배치를 확인하도록 안내합니다.

플러그인이 macOS 화면 기록 권한을 직접 요구하거나 자동으로 허용하지 않습니다. 실제 화면을 캡처해 프리뷰를 만들지 않으며, 오류 안내·로그에 화면 내용이나 장치 ID를 포함하지 않습니다. 로컬 MCP 이용 가능 여부와 로그인 조건은 실제 서버 응답에 따라 안내하고, 새로운 계정·토큰 입력란은 추가하지 않습니다.

## 구현과 검증 순서

1. 합성 응답으로 미러링 응답 파서, 같은 상태 처리, 명령 1회 전송, 전환과 시간 초과 정책을 구현·검증합니다.
2. 새 키 동작, 설정 설명과 공유 상태 표시를 연결합니다. 버튼별 설정과 기존 전원·씬·밝기 회귀 테스트를 통과시킵니다.
3. 명시적으로 승인된 설치 환경에서 정확한 시험 패키지를 설치합니다. 임시 프로필 선택만으로 공유 플러그인 설치가 격리되지는 않으므로 기존 프로필 영향과 복구 절차를 먼저 확인합니다.
4. 실제 시작·정지와 USB 출력, 다른 스트리밍과의 충돌, 이전 상태 복원, 자동 실행을 시험합니다. 권한 허용이나 조명 변경이 필요한 시험은 사용자 동의 후 수행합니다.
5. 결과에 따라 지원 범위를 기록한 뒤 새 버전 부여·배포 여부를 결정합니다. 기존 beta.4 설치 파일을 덮어쓰지 않습니다.

| 검증 항목 | 합격 조건 |
| --- | --- |
| 시작과 정지 | 각 키가 의도한 엔진 상태로 바뀌고 NL82K2에서 실제 출력 변화 확인 |
| 중복 입력 | 시작 중 연타·다른 키 입력으로 시작/정지가 중복 전송되지 않음 |
| 외부 상태 변경 | Desktop UI로 바꾼 상태를 표시하고 다음 요청 전에 재조회 |
| 응답 지연과 유실 | 자동 변경 재전송 없음, 읽기 재확인과 불확실 상태 표시 |
| 앱 완전 종료 | 시작·전환 옵션 ON/OFF 각각 검증, 정지 키는 앱을 실행하지 않음 |
| Desktop 자체 시작 옵션 | `Screen Mirror on App Launch` ON/OFF 모두에서 앱 실행이 필요한 첫 전환은 켜기를 의도하고, 이미 자동 시작된 미러링을 다시 정지하지 않음 |
| 화면 기록 권한과 잘못된 배치 | 허위 성공 표시와 자동 권한 변경 없이 안내 |
| 복수 대상과 다른 스트리밍 | 대상 전체 영향과 상호 배타 동작을 확인하고 제품 설명에 반영 |
| 중지 후 복원 | 저장 씬·단색·꺼진 상태와 중간 수동 변경의 결과를 각각 기록 |
| 기존 버튼과 동시 조작 | 밝기·씬·전원 요청과 충돌하거나 늦은 명령이 실행되지 않음 |
| USB 분리와 화면 변경 | 연결 복귀, 모니터 분리·재연결·절전 이후 상태를 재확인 |
| 설치와 설정 유지 | 기존 프로필·제목·장치·씬·자동 실행 값 유지 |
| 개인정보 | 패키지·로그에 화면 데이터나 개인 설정이 포함되지 않음 |

## 근거와 재확인 지점

- 설치 앱 3.0.1의 Screen Mirror 화면 및 로컬 MCP `tools/list`, `get_screen_mirror_status` 읽기 결과입니다. 이번 조사에서는 시작·정지 명령을 호출하지 않았습니다.
- 설치 앱 `app.asar` 내부 `minified/main.js`의 미러링 MCP 등록, `web/chunk-FmHseHXx.js`의 `externalScreenMirrorOperation`, `getMirrorRequest`, `setStreamingDevicesToPreviousState`, `stopStreaming` 경로를 확인했습니다. 최소화된 파일명·함수·구현은 앱 업데이트 시 달라질 수 있습니다.
- [Nanoleaf 공식 MCP 안내](https://nanoleaf.me/en-us/pages/works-with-mcp)는 Screen Mirror 시작·정지를 설명하지만, 개별 제품 지원은 버전에 따라 달라질 수 있습니다. 위 계획의 정확한 명령 규격은 현재 설치 앱의 로컬 조회에 근거합니다.
