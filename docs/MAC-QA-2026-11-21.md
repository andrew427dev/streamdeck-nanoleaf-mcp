## Startup and diagnostics follow-up

Desktop was quit through its normal menu. A read-only process/port check found zero main/helper processes and a closed local MCP port. Connection diagnostics displayed unavailable/`APP_CONNECTION`, and the settings-list refresh displayed guidance to open Desktop and enable MCP. During a three-minute process/port observation neither read-only action launched Desktop.

**Disabled launch option: passed for one physical trial.** The tester pressed QA Scene with the option temporarily disabled and reported that Desktop did not launch. Post-trial readback confirmed zero main/helper processes and a closed port. The observer finished before the response, so no uninterrupted trace through the entire user-response interval is claimed. The option was restored to true through the inspector and verified in the saved QA setting. **Enabled launch option: initial cold start passed; immediate quit/relaunch failed.** The tester confirmed that the first automatic launch and scene worked, but the subsequent Command-Q/immediate-repress did not. The observer saw the first main process at 19.470 seconds and MCP readiness at 23.154 seconds. At 32.241 seconds (12.771 seconds after the main process appeared), the port closed while the same main process and three helpers remained. The main process did not disappear until 137.349 seconds, approximately **105.1 seconds after the port first closed**. The inspector displayed timeout/uncertainty guidance, and the QA log recorded `APP_TIMEOUT`.

The tester confirmed manually quitting or reopening Desktop after the failure. The subsequent new process IDs and restored connection are therefore **manual recovery evidence**, not automatic recovery. The precise second-input time and whether the manual recovery used force quit were not captured. A read-only sampling attempt could not inspect the old process because it had already exited; no diagnostic stack or root cause was obtained. The assistant did not terminate/relaunch Desktop during this recovery or send a corrective light command.

After recovery, read-only state queries and the actual inspector reported a ready connection, **power ON, brightness 52%, the same 16 saved scenes, mirroring OFF**. The temporary launch-OFF setting had already been restored to true; the QA dial text size remained large. QA remains installed for further testing.

This reproduces a user-visible rapid-relaunch failure with residual Desktop processes. It resembles the older retained-beta.3 quit incident, but it does not establish a common cause, prove a plugin regression or show that this candidate fixed the issue. The strict first-15-second complete-exit/relaunch acceptance remains **not passed**; do not convert the first successful cold start or later manual recovery into a pass for it.
