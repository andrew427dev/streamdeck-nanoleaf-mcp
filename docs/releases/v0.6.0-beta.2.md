Post-release documentation update: **2026-10-23**. This records new hardware evidence without changing the release version, tag, installers, installed plugin or saved settings.

### Changes

- Stop invalidated power/scene/brightness input and scene-list loading from launching Nanoleaf Desktop late on both OS paths. Recheck validity at the app execution boundary, including after Windows installation discovery.
- Bring the common unsent-input cancellation safeguards into the Mac release line. Disappearance, reappearance, target-device changes and relevant control-setting changes invalidate old work. Discard stale event settings instead of directing an old request to the newly selected light.
- Preserve other valid participants in shared startup. Cancelling an input does not terminate an already-running app, cancel a still-valid request or undo/replay a command already sent. Display-only preferences retain otherwise valid work.
- Reconcile public/private version and validation records. Preserve all plugin/action identifiers, saved settings fields and per-control app-launch opt-in/defaults; no profile migration is introduced.

### Validation and limits

- The new-version local Node.js **24.13.1** suite passed **316/316 tests**. Both OS installer targets passed official validation/packaging and internal archive checks, with **50 allowlisted files** each.
- Before release-version assignment, the focused 107-case regression group passed 100 repetitions (**10,700 passes**). Those Mac-hosted mocked checks are separate historical evidence, not a hardware endurance test or replacement for release-source CI.
- [Release-source CI](https://github.com/andrew427dev/streamdeck-nanoleaf-mcp/actions/runs/39925750730) and [tag CI](https://github.com/andrew427dev/streamdeck-nanoleaf-mcp/actions/runs/39925942804) each passed both macOS and Windows jobs, with **316 tests per job** and packaging. The published assets were downloaded again and their checksums matched the inspected files. CI uses synthetic devices and does not validate actual Nanoleaf Desktop, USB or a physical Stream Deck.
- **Mac post-release verification — 2026-10-23:** a separately approved in-place upgrade installed public v0.6.0-beta.2 / manifest **0.6.0.2**. All **50 installed package files** matched the public Mac installer, and all **32 profile files** were unchanged. The tester confirmed existing physical power OFF→ON, saved-scene and brightness −/+ keys worked normally.
- **Mac fully-closed-app test — 2026-10-23:** after a normal complete quit, zero related Nanoleaf processes and the closed local MCP port were verified. The tester pressed an existing auto-launch-enabled scene key once and confirmed that Desktop launched and the scene worked. Follow-up read-only status checks succeeded; all **82 installed-package/profile files** remained unchanged through this check. This proves one scene-path cold start, not repeated delayed-start/cancellation, all-button, dial/touch or recovery coverage.
- **Windows tester report — 2026-10-23:** the **physical-button section passed**, according to the tester. Exact OS/app/hardware versions, per-action details and separate 0%/100% boundary or power-side-effect results were not supplied; no independent Windows telemetry was captured. This is limited reported end-to-end evidence, not broad Desktop/MCP/USB certification.
- **Remaining hardware acceptance:** Mac exact-build dial/touch/display, repeated delayed-start/cancellation and error/recovery regression; Windows registered-installation discovery, PowerShell/native automatic launch, installation/reinstallation/settings retention, dials/touch/scaling, brightness boundaries/power effects and restart/sleep/reconnection; and broader fresh-install/OS/hardware/Desktop-update coverage. Earlier hardware observations remain attributed to their named builds, not silently promoted to this version.

### Important known limitations

- **Mac mirroring is not fixed.** Stopping can change power or cause a visible transition. The previous v0.5.0-beta.2 also reported engine ON without screen-colour output; a tester recovered by restarting Desktop, but the cause remains unresolved. Engine status is not proof of output.
- The private v0.5.0-beta.3 after-stop power compensation is **not included**. Its failed no-flash cases are not declared fixed. Screen Mirror's separate request/`prepareApp` path is unchanged; this release is not a mirror cancellation or reliability fix.
- Brightness-only requests can still trigger Desktop power changes at 0% or positive brightness. Windows boundary/power-side-effect behavior remains unverified. Windows 10/ARM64, Wi-Fi/LAN lights and other USB models are outside the verified scope; portable/unregistered Windows Desktop installations cannot be auto-launched.

Publication itself left the maintainer's private Mac v0.5.0-beta.3 installation untouched. The subsequently approved in-place update installed public v0.6.0-beta.2 while retaining existing profiles/settings; that public version excludes the private build's experimental compensation and is not a mirror fix. This documentation-only follow-up changes neither the installed plugin/settings nor release assets/tag. Mirror improvement and Marketplace submission remain on hold. See the updated [validation](https://github.com/andrew427dev/streamdeck-nanoleaf-mcp/blob/main/docs/VALIDATION.md), [status](https://github.com/andrew427dev/streamdeck-nanoleaf-mcp/blob/main/docs/STATUS.md) and [Windows acceptance checklist](https://github.com/andrew427dev/streamdeck-nanoleaf-mcp/blob/main/docs/WINDOWS.md); documents at the immutable release tag remain the publication-time snapshot.

## 한국어

**USB 연결형 Nanoleaf PC Screen Mirror Lightstrip(NL82K2)**을 Nanoleaf Desktop의 로컬 MCP로 제어하는 시험판입니다. Wi-Fi/LAN 제품용 플러그인이 아닙니다. 위 표에서 **Mac 베타** 또는 **Windows 11 x64 실험적 베타**를 선택하고, 함께 제공한 체크섬을 확인해 주세요. Windows 화면 미러링은 지원하지 않습니다.

이번 **2026-10-23 배포 후 문서 갱신**은 새 검증 근거를 기록하며, 릴리스 버전·태그·설치 파일·기존 설치본·설정은 변경하지 않습니다.

### 변경 사항

- 전원·씬·밝기 입력이나 씬 목록 로딩이 무효화됐을 때 앱을 뒤늦게 실행하지 않도록 양쪽 OS에서 보완했습니다. Windows 설치 정보 탐색 뒤에도 실행 직전에 다시 확인합니다.
- 공통 소스의 전송 전 입력 취소를 Mac 배포 계열에 포함합니다. 프로필에서 동작이 사라지거나 다시 나타나고, 장치·관련 설정이 바뀌면 오래된 요청을 폐기합니다. 이전 이벤트를 새로 선택한 장치로 바꾸어 실행하지 않습니다.
- 유효한 다른 요청의 앱 시작은 유지하고, 이미 실행된 앱을 강제로 종료하지 않습니다. 이미 전송한 조명 명령을 되돌리거나 재전송하지 않습니다. 표시만 바꾸는 설정은 유효한 입력을 취소하지 않습니다.
- 버전·검증 문서를 정리했습니다. 플러그인·동작 식별자, 저장 설정과 버튼별 앱 실행 기본값·선택값은 유지하며 프로필 이전은 필요하지 않습니다.

### 검증과 미검증 범위

- 새 버전에서 Node.js **24.13.1** 자동 시험 **316개**와 두 OS의 공식 설치 파일 검사·패키징·내부 ZIP 검사를 통과했습니다. 각 파일은 공개 허용 목록 **50개 파일**로 구성됩니다.
- 버전 부여 전 집중 회귀 **107개 × 100회 = 10,700개**를 통과한 기록도 있습니다. 실제 기기 내구 시험이 아니며 새 배포 커밋의 CI를 대신하지 않습니다.
- 위에 연결한 정확한 배포 소스·태그 CI에서 Mac·Windows 작업이 각각 **작업당 316개 시험**과 패키징을 통과했습니다. 공개 후 다시 받은 설치 파일도 검사본과 체크섬이 일치했습니다. 자동 시험은 모의 장치를 사용하며 실기기 호환성 인증은 아닙니다.
- **Mac 배포 후 검증 — 2026-10-23:** 별도 승인된 업데이트로 공개 v0.6.0-beta.2 / 설치 정보 **0.6.0.2**를 설치했습니다. 공개 패키지의 **50개 파일 전체 일치**, **기존 프로필 파일 32개 변경 없음**을 확인했고, 사용자가 기존 물리 키의 전원 OFF→ON·저장된 씬·밝기 −/+ 정상 작동을 확인했습니다.
- **Mac 앱 완전 종료 후 자동 실행 — 2026-10-23:** 정상 종료 후 관련 프로세스 0개·로컬 MCP 포트 닫힘을 확인했습니다. 사용자가 자동 실행을 켜둔 기존 씬 버튼을 한 번 눌러 앱 실행과 씬 적용의 정상 작동을 확인했고, 이후 읽기 전용 상태 조회도 성공했습니다. 이 시험 전후 **설치·프로필 파일 82개**는 동일했습니다. 씬 경로 1회의 결과이며 반복·지연 실행 취소나 모든 버튼·다이얼·터치·복구 조건의 통과는 아닙니다.
- **Windows 사용자 보고 — 2026-10-23:** **물리 버튼 섹션 검증 완료**를 보고받았습니다. 정확한 운영체제·앱·기기 버전, 개별 동작별 결과, 0%/100% 경계값·전원 부수 효과는 따로 전달되지 않았고 Windows 상태를 독립 수집하지도 않았습니다. 제한된 실제 제어 보고이며 전체 Desktop·MCP·USB 호환성 검증으로 확대하지 않습니다.
- **미검증 유지:** Mac의 정확한 새 빌드에서 다이얼·터치·표시, 반복·지연 실행 취소와 오류·복구 회귀; Windows의 설치 정보·PowerShell·실제 자동 실행·설치/재설치·설정 유지·다이얼·터치·배율·밝기 경계값·전원 부수 효과·재부팅/절전/재연결; 양쪽 OS의 신규 설치와 다른 운영체제·기기·Desktop 업데이트 호환성입니다. 이전 버전의 실기기 기록을 새 버전 합격으로 바꾸지 않습니다.

### 알려진 제한과 유지 사항

- **Mac 미러링 중지 시 전원 변화·깜빡임과 ON 표시인데 화면 색상을 출력하지 않는 문제는 해결하지 않았습니다.** 앱 재실행으로 복구한 과거 사례는 영구 해결의 근거가 아닙니다.
- 비공개 **v0.5.0-beta.3 사후 전원 보정은 포함하지 않았고**, 미러링의 별도 앱 실행 경로도 바꾸지 않았습니다. 미러링 개선판으로 설치하지 마세요.
- 밝기만 요청해도 Desktop이 0%에서 끄거나 양수에서 켤 수 있습니다. Windows의 경계값·전원 부수 효과는 별도 검증이 필요합니다.
- 공개 작업 당시에는 Mac의 비공개 beta.3를 유지했고, 이후 별도 승인된 업데이트로 기존 프로필·설정을 유지한 채 공개 v0.6.0-beta.2를 설치했습니다. 이번 문서 갱신은 현재 설치본·설정·배포 파일·태그를 변경하지 않습니다. 변경되지 않는 릴리스 태그 안의 문서는 공개 당시 기록이며, 배포 후 결과는 main 문서와 릴리스 설명에 반영합니다. 미러링 개선과 Marketplace 제출은 계속 보류합니다.
